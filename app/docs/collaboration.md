# Multiplayer canvas

Paper's collaboration relay runs automatically with `npm run dev`, `npm run preview`, and the Docker Compose API service. It shares the app's origin, has no hosted-service dependency, and works across browsers and devices. For another device on your network, serve Paper with `npm run dev -- --host 0.0.0.0` or, after `npm run build`, `npm run preview -- --host 0.0.0.0`. Open that host's address on both devices. Static file hosting alone does not run the relay.

Canvases open in solo mode, with local editing and cloud autosave sending no collaboration requests. Opening **Canvas collaborators** in the header keeps the canvas solo. Click **Share**, **Invite**, or **Copy invite link** to start a session; opening a valid `#room=<id>` invitation connects immediately. Each project has a distinct room. Opening an invitation creates or opens a separate local project with that room ID, preserving the visitor's other projects. Anyone with the invitation can edit the room. Profile names appear on presence chips, cursor labels, and selection outlines. The invite URL is available to select manually when clipboard permissions are unavailable. After sharing, closing the panel keeps the session live; switching or creating a project opens that canvas in solo mode.

Click **Follow** beside another designer to track their world-space viewport center and zoom. Different screen sizes keep the same center. Pan, scroll, a canvas pointer down, Escape, or **Stop following** returns control to your camera. Following someone who is away or already following another person is disabled to prevent feedback loops.

## Synchronization

- Local canvas mutations remain immediate. Pending writes coalesce at 30 Hz and use same-origin JSON requests; server-sent events deliver updates as soon as the relay accepts them.
- Elements use Lamport-clock, actor-ordered field registers. Edits to separate properties, including nested paints, merge independently. Simultaneous writes to one property resolve deterministically. Document collections (tokens, the style library, prototype interactions, and canvas shaders) resolve as atomic registers.
- Existence tombstones prevent late property edits from resurrecting deleted layers. An explicit restore/undo can revive them. Child lists derive from surviving nodes' parent and ordering registers, preserving concurrent additions. Concurrent parent cycles break deterministically; a concurrently added child of a deleted parent becomes a root layer.
- The relay validates the merged document before accepting each batch. Incompatible semantic edits (for example a component operation that would leave invalid references) are rejected atomically. The sender restores the accepted document and sees an explanation in the collaboration panel.
- Cursor and camera coordinates are in world space, excluding the 20 px rulers. Cursors interpolate using elapsed frame time and direct DOM transforms on a demand-driven animation loop. Reduced motion bypasses interpolation. Remote selections respect ancestor rotation and zoom.
- Selection, cursor, presence, and camera are ephemeral and never enter document history. Remote document edits rebase local history and active gesture baselines, so undo does not revert another designer's accepted changes. The older MCP tab channel carries settings and agent activity; room synchronization owns canvas edits.
- Reconnection receives a complete register snapshot before merging the local pending queue. Duplicate delivery is harmless. A fresh stream snapshot closes the join-to-stream race. Clients retain a random session credential across join retries, so a lost initial response cannot lock the editor out of its own session. Connection generations discard obsolete joins and stream events. Presence is active, idle after 60 seconds without edits/pointer activity, or away when the page is hidden/disconnected.

## Hosting and retention

The relay is an active-session service: rooms remain in server memory and expire after 30 minutes without connected clients. Restarting the server clears its rooms. The first browser to rejoin seeds the room from its locally saved document. Local workspace autosave and JSON exports remain the durable copies; unsent edits survive network interruptions while that editor remains open. Project names and engineering-grid preferences remain local to each browser (the existing MCP tab channel shares these between local tabs).

A reverse proxy must forward `/__paper_collaboration/` to the same Paper process and permit long-running SSE responses without buffering. Room invitations act as capability links; deploy behind your existing access-controlled host if needed. The relay checks request origins, issues per-session tokens, bounds request sizes/room membership, and disconnects streams that cannot keep up. It does not implement account permissions or durable server-side project storage.

Docker Compose routes `/__paper_collaboration/` through Nginx to `paper-api:3001`, with buffering, caching, and compression disabled and one-hour streaming timeouts. Set `PAPER_PUBLIC_URL` to the browser-facing origin, including its scheme and any non-default port, so backend origin checks accept your deployment. Collaboration invitation links and session tokens work independently of cloud account sign-in. The API closes collaboration streams when it shuts down.

## Verification

`npm run build` checks browser, Vite server, and MCP TypeScript and creates the production bundle. `npm test` includes merge convergence, concurrent insert/delete/reparent behavior, undo rebasing, register validation, and the actual HTTP/SSE middleware. Socket-free activation tests exercise solo mode, invitation actions, clipboard/native-share fallbacks, cloud room IDs, hash changes, and session cleanup. Client lifecycle regression tests exercise optimistic edits before joining, offline replay, lost join responses, obsolete connection responses, follow cancellation, and active/idle/away presence without opening a server socket. `npx playwright test e2e/collaboration.spec.ts` checks zero collaboration requests during solo editing and cloud autosave, explicit invitations, immediate room joins, room/project transitions, two isolated browser workspaces, cursors, remote selection alignment, viewport follow, and edits queued during a network interruption.
